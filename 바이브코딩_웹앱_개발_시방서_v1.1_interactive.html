2. 범위 (In / Out)

✅ 이번 버전(1.0) 범위에 포함 (In)
  • 이메일 회원가입 / 로그인 / 로그아웃 (Supabase Auth)
  • 수입·지출 거래 등록·수정·삭제 (CRUD)
  • 월별 달력 보기 (거래 있는 날짜 표시, 날짜 클릭 시 상세)
  • 월별 합계 요약 (수입/지출/잔액, 카테고리별 비중)
  • 카테고리 기본 제공 + 사용자 추가
  • 행 단위 보안(RLS) 적용, 모바일 우선 반응형
⛔ 이번 버전 범위 제외 (Out) — 추가하지 말 것
  • 환율 변환, 자산·투자 관리, 예산 설정, 알림·리마인더
  • 다른 사용자와의 공유·가계부 합치기
  • 모바일 앱(네이티브), 오프라인 동기화
  • 결제 연동, 다국어(i18n), 관리자 페이지
  • 기타 가이드에 없는 임의 기능 — 요구사항 변경 시 이 문서를 먼저 수정할 것

3. 기능 요구사항 (FR-001 ~ FR-006)

각 기능에는 수용 기준(Acceptance Criteria)과 AI 프롬프트 템플릿이 붙어 있습니다. 수용 기준이 전부 통과해야 해당 기능이 "완료"입니다.

FR-001 이메일 회원 인증 (회원가입·로그인·로그아웃)
설명: Supabase Auth로 이메일+비밀번호 인증을 구현. 로그인하지 않으면 모든 페이지 접근 시 로그인 화면으로 이동. 설정 시작: Supabase 콘솔 열기 RLS 개념 문서
  • AC-001.1 이메일+비밀번호(8자 이상)로 회원가입이 가능하다
  • AC-001.2 가입 성공 시 자동 로그인되어 홈 화면으로 이동한다
  • AC-001.3 잘못된 비밀번호 입력 시 한글 오류 메시지가 표시된다
  • AC-001.4 중복 이메일 가입 시 중복 안내 메시지가 표시된다
  • AC-001.5 로그아웃 버튼 클릭 시 세션이 종료되고 로그인 화면으로 이동한다
  • AC-001.6 브라우저 새로고침 후에도 로그인 상태가 유지된다
▶ AI 프롬프트: "Next.js App Router와 Supabase Auth로 이메일 회원가입/로그인/로그아웃을 구현해 줘. 로그인 안 한 사용자는 모든 페이지에서 /login으로 리다이렉트하고, 로그인 상태는 새로고침 후에도 유지돼야 해. 오류 메시지는 한국어로 표시하고, 비밀번호는 8자 이상 검증해 줘."
FR-002 거래 등록·수정·삭제 (CRUD)
설명: 수입/지출 내역을 등록·조회·수정·삭제. 본인 데이터만 접근 가능(RLS).
  • AC-002.1 등록 폼에 유형(수입/지출), 금액, 날짜, 카테고리, 메모 입력란이 있다
  • AC-002.2 저장 버튼 클릭 시 목록에 즉시 반영된다
  • AC-002.3 수정 버튼으로 기존 내역을 변경할 수 있다
  • AC-002.4 삭제 버튼 클릭 시 확인 문구("정말 삭제할까요?")가 뜨고, 확인 시에만 삭제된다
  • AC-002.5 금액은 0보다 큰 숫자만, 날짜·유형은 필수. 미충족 시 입력 화면에서 검증 오류가 표시된다
  • AC-002.6 다른 사용자의 거래는 조회·수정·삭제 모두 불가능하다 (RLS 검증)
▶ AI 프롬프트: "Supabase 테이블 transactions에 대해 수입/지출 거래를 등록·목록 조회·수정·삭제하는 CRUD UI를 만들어 줘. 폼은 유형(수입/지출), 금액, 날짜, 카테고리, 메모로 구성하고, 삭제 시 확인 다이얼로그를 띄워 줘. 금액은 0 초과 숫자만 허용하고, 모든 요청은 로그인 사용자 본인(user_id)만 접근하도록 해 줘."
FR-003 월별 달력 보기
설명: 월 단위 달력에 거래가 있는 날짜를 표시하고, 날짜를 클릭하면 해당일 거래 목록을 보여줌.
  • AC-003.1 이번 달 달력이 기본 표시된다 (월~일 그리드, 날짜·요일 표시)
  • AC-003.2 거래가 있는 날짜에는 지출 합계(또는 마커)가 표시된다
  • AC-003.3 날짜 클릭 시 해당일의 거래 목록(금액·카테고리·메모)이 표시된다
  • AC-003.4 이전/다음 월 이동 버튼이 동작한다
  • AC-003.5 오늘 날짜는 시각적으로 강조된다
▶ AI 프롬프트: "월별 달력 컴포넌트를 만들어 줘. 각 날짜 셀에 그날의 지출 합계를 표시하고, 날짜를 클릭하면 아래에 해당일 거래 목록이 뜨게 해 줘. 이전/다음 월 이동 버튼과 오늘 날짜 강조를 포함하고, 모바일에서도 잘 보이게 반응형으로 만들어 줘."
FR-004 월별 요약 (합계·카테고리 비중)
설명: 선택한 달의 수입·지출·잔액과 카테고리별 지출 비중을 한눈에 보여줌.
  • AC-004.1 이번 달 수입 합계, 지출 합계, 잔액(수입-지출)이 카드에 표시된다
  • AC-004.2 카테고리별 지출 비중이 간단한 바 차트로 표시된다
  • AC-004.3 달력에서 이동한 월에 맞춰 요약도 함께 갱신된다
  • AC-004.4 거래가 없으면 "기록이 없습니다" 안내가 표시된다
▶ AI 프롬프트: "선택한 월의 수입 합계, 지출 합계, 잔액을 카드 3개로 보여주고, 카테고리별 지출 비중을 바 차트로 표시해 줘. 달력의 월 이동과 연동되게 하고, 데이터가 없으면 안내 문구를 보여 줘."
FR-005 카테고리 관리
설명: 기본 카테고리(식비·교통·쇼핑·주거·문화·기타)를 제공하고, 사용자가 직접 추가·수정 가능.
  • AC-005.1 기본 카테고리 6종(식비, 교통, 쇼핑, 주거, 문화, 기타)이 제공된다
  • AC-005.2 설정 화면에서 카테고리 추가가 가능하다
  • AC-005.3 추가한 카테고리는 거래 등록 폼 선택지에 즉시 반영된다
  • AC-005.4 카테고리 삭제 시 해당 카테고리의 기존 거래는 "기타"로 처리된다
▶ AI 프롬프트: "카테고리를 관리하는 기능을 추가해 줘. 기본값은 식비·교통·쇼핑·주거·문화·기타이고, 사용자가 추가/수정/삭제할 수 있게 해 줘. 삭제된 카테고리의 기존 거래는 '기타'로 바뀌고, 거래 등록 폼의 선택지에 실시간 반영되게 해 줘."
FR-006 데이터 보안 (RLS · 시크릿 관리) — 필수
설명: 모든 테이블에 행 단위 보안(RLS)을 적용하고, API 키 등 시크릿은 환경변수로만 관리. 바로 실행: Supabase SQL Editor RLS 가이드 Vercel 환경변수 가이드
  • AC-006.1 profiles·transactions 테이블 모두 RLS가 활성화되어 있다
  • AC-006.2 모든 정책이 "auth.uid() = user_id" 조건으로 본인 데이터만 허용한다
  • AC-006.3 클라이언트에는 anon 키만 노출되고, 서비스 롤 키는 서버(Supabase 함수/환경변수)에서만 사용한다
  • AC-006.4 .env 파일에 시크릿이 있고, .gitignore에 .env가 포함되어 GitHub에 업로드되지 않는다
  • AC-006.5 배포 환경(Vercel)에도 동일한 환경변수가 설정되어 있다
▶ AI 프롬프트: "profiles와 transactions 테이블에 RLS(Row Level Security)를 활성화하고, 'auth.uid() = user_id' 조건으로 본인이 만든 행만 조회/삽입/수정/삭제할 수 있는 정책을 만들어 줘. 클라이언트에는 anon 키만 쓰고, 서비스 롤 키는 환경변수로 관리되게 해 줘. .env를 .gitignore에 추가해 줘. 마지막으로 RLS가 제대로 막히는지 테스트해 줘."

5-3. RLS 정책 (SQL 예시)

alter table public.transactions enable row level security;
alter table public.profiles     enable row level security;

create policy "본인만 조회" on public.transactions
  for select using (auth.uid() = user_id);
create policy "본인만 등록" on public.transactions
  for insert with check (auth.uid() = user_id);
create policy "본인만 수정" on public.transactions
  for update using (auth.uid() = user_id);
create policy "본인만 삭제" on public.transactions
  for delete using (auth.uid() = user_id);
-- profiles에도 동일한 패턴 적용

6. API 엔드포인트

인증(회원가입·로그인)은 Supabase Auth가 담당하므로 별도 API를 만들지 않습니다. 거래 데이터는 아래 API(Next.js Route Handler)로 제공합니다.

메서드경로인증설명성공 응답
GET/api/transactions?month=YYYY-MM필수해당 월 거래 목록 (본인만)[{id, type, amount, category, memo, txn_date}]
POST/api/transactions필수거래 등록{id, ...} (201)
PATCH/api/transactions/:id필수거래 수정{id, ...}
DELETE/api/transactions/:id필수거래 삭제{ok: true}
GET/api/summary?month=YYYY-MM필수월별 수입·지출·카테고리 집계{income, expense, balance, byCategory[]}
⚠️ 규칙: ① 모든 엔드포인트는 서버에서 세션 확인 후 user_id 기준으로만 동작 ② 응답에 다른 사용자의 데이터 절대 포함 금지 ③ 에러 시 한글 메시지와 적절한 HTTP 상태 코드 반환(401/403/404/400).

9. 배포 전 최종 점검 (보안 체크리스트)

점검 도구를 열어 두세요: Supabase 대시보드 Vercel 대시보드 GitHub 저장소

  • ☐ API 키가 코드에 박혀 있지 않고 전부 환경변수(.env)로 옮겼는가
  • ☐ profiles·transactions 모두 RLS가 켜져 있고 정책이 "본인만"인가
  • ☐ AI가 설치하라고 한 패키지 이름이 npm/공식 문서에 실제로 존재하는가
  • ☐ 로그인·권한 흐름(세션 만료, 타인 데이터 접근 차단)을 손으로 한 번 검토했는가
  • ☐ Vercel Hobby·Supabase Free 한도(빌드·대역폭·DB 용량)를 확인했는가
  • ☐ 실제 서비스 데이터 없이 더미 데이터로 테스트했는가 (격리 샌드박스 원칙)
