1. 플랫폼 개요 (대상 시스템 재정의)

항목내용
플랫폼명VibeDeploy Hub (가칭)
한 줄 정의사용자 입력(프롬프트 한 줄)으로 GitHub 저장소·CI/CD·호스팅·도메인·DNS·SSL까지 일원 자동 연결하는 웹 서비스.
타깃 사용자코드를 모르는 기획자·디자이너·초보 개발자, 다수 사용자 SaaS 운영자.
핵심 약속 (SLO)신규 로그인 사용자가 도메인 1개만 입력하고 10분 이내에 발급된 HTTPS URL에서 본인 앱을 확인할 수 있다.
기술 스택 (플랫폼 자체)Next.js 15 (App Router) · TypeScript · Supabase (Postgres + Auth) · Vercel 또는 Cloudflare Pages 호스팅 · GitHub 자동화 · OpenAI/Anthropic 코드 생성 LLM · Cloudflare DNS + SSL
Two-Track 운영 원칙샌드박스(파일럿 자동화) ↔ 운영(격리된 토큰 + RLS + encrypt-at-rest) 분리. 운영 측 코드/토큰은 자동화 샌드박스에서 작성 후 사람이 검수 후 적용. (CIO.com 투 트랙 권고 적용)

24.2 Step ① · Supabase

  1. supabase.com/dashboard → "Sign In" → GitHub 또는 이메일 가입.

  3. API 키 회수: 좌측 Settings → API Keys (sb_publishable_, sb_secret_). 레거시 라벨 anon/service_role과 동일 키.

24.3 Step ② · GitHub (v2.1 모순 수정: "OAuth 1회"는 사용자가 PAT와 App 설치 중 선택)

  1. github.com/signup → 이메일 인증 + 2FA 활성화.
  2. 선택 A (권장): Fine-grained PAT 발급 — github.com/settings/personal-access-tokens/new → Generate new token.
    • Permissions:
      • Contents: Read and write (FR-004 PUT /contents)
      • Metadata: Read-only (모든 REST 자동 요구)
      • Actions: Read and write (FR-005 workflow_dispatch)
      • Members: Read-only (조직 저장소 자동 생성 시 필요)
      • Repository administration: Read and write (저장소 자동 생성 POST /user/repos)
    • Expires: 90일 권장 (단기 노출 시 자동 회전)
  3. 선택 B (팀/조직 권장): GitHub App 설치 — 플랫폼 자체 GitHub App 운영 → OAuth App flow + Installation token → 다수 저장소 권한 일괄.
  4. 발급된 토큰은 github_pat_ 접두사. 서버 env GITHUB_TOKEN에 저장. 클라이언트 번들 금지.
